# ADOMS 데모 2차 — 용인특례시 (시연본)

Next.js 15(App Router) · TypeScript · 서버 컴포넌트.
설계 근거: `01_설계\(설계)ADOMS_데모2차_화면·기능설계서_20260920_v0.1.html`

## 띄우기

```
npm install
npm run dev        # http://localhost:3100
```

## 데이터 원천 — 두 갈래

`lib/data.ts` 한 곳에서만 데이터를 읽는다(메모리 `adoms-ui-data-access-rule`).

| 조건 | 읽는 곳 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`·`NEXT_PUBLIC_SUPABASE_ANON_KEY` 가 있으면 | Supabase REST · 스키마 `adoms2` 의 **뷰** |
| 없으면(기본) | 데모 DB 판 폴더의 **seed CSV** (`_데모_용인시_20260920\ops_v0.2_… → ops_v0.1_…`) |

같은 시드라 두 경로의 결과가 같다. Supabase 적재 전에도 화면을 만들 수 있게 둔 것이다.
접속 정보는 `.env.local` 에 둔다(`.env.local.example` 참고) — **anon(publishable) 키만** 쓴다.
service_role 키와 DB 비밀번호는 앱 어디에도 넣지 않는다.

CSV 판 위치를 바꾸려면 `ADOMS_OPS_DIR` 환경변수로 가리킨다.

## 화면

| 경로 | 화면 | 비고 |
|---|---|---|
| `/` | 대시보드 | 재해 구분별 이행률 · 부서 진도 · 개정 알림 |
| `/duties` | 의무 이행사항 — **3축 선택** | 시연 이슈 ① |
| `/duties/list` | 의무 목록(필터) | 재해·조건부·이행 유형 |
| `/duties/[key]` | 의무 상세 | 근거 조문 원문 · 서식 · 주기 |
| `/targets` | 관리대상 현황 | 유형 카드 → 자산 목록 |
| `/targets/[id]` | 자산 상세 — **법령 그룹별 의무** | 시연 이슈 ② (터널 → 재난안전법) |
| `/tasks` | 내 업무 | 이행 상태 × 결재 상태 2축 |
| `/inspections` | 이행점검·조치 | 확보의무 대분류 × 부서 매트릭스 |
| `/contracts` | 도급·용역·위탁 | 중처법 제5조 |
| `/ceo` | 기관장 예방활동 | 활동·예산·교육·종사자 의견 |
| `/settings` | 설정 | 조직·서식·개정·데이터 출처 |

`?role=ceo|gm|mgr|road|water` 로 보는 사람을 바꾼다(시연용 역할 전환).

## 화면에서 지키는 것

- **숨기지 않는다** — 조건부 의무·자산 대장 없음·분류 추론(검수 전)·정본 미반영을 배지로 드러낸다.
- **정본은 읽기 전용** — 의무·법령·조문은 고치지 않는다. 운영 데이터(과제·계약·활동)만 이 시스템이 관리한다.
- **예시 데이터 표시** — 계약·기관장 활동·예산·사고는 시연용으로 만든 값이고 화면에 그렇게 적는다.
- 같은 조문에 우산 의무가 여러 개 붙어 행이 겹치는 것은 화면에서만 접는다(`foldByUnit`) — 데이터는 건드리지 않고 「같은 조문 의무 n」으로 밝힌다.
