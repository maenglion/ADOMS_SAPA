# 관리층 v1.1 — 덩어리 조문 고시·지침의 의무(잠정) · **용인시 시연 전용**

**만든 날** 2026-09-20 · **만든 곳** 수집 완결성 포크 · **정본이 아니다** · **그래프DB에 싣지 않는다**

## 왜 있나

사용자 지시(09-20): 「덩어리 행에 대해 `unit` 을 쪼개지 않고 **이미 있는 구조**(unit · obl_master · obl_item)로 담아 달라.
정본DB에 반영하려는 게 아니라, 시연을 준비 중인 다른 채팅에서 **용인시의 체육시설 관리 의무 등**을 반영해 의무리스크를 구성하려는 것이다.
그래프DB에는 요청하지 말고, 의무리스트를 뽑아 **용인시 시연DB에만** 반영하면 된다.」

법제처가 기술기준·설계지침·진단기준 고시를 **통짜로** 준다(덩어리 행 84 · 41문서 · 최대 78,117자 한 행).
정본 `unit` 은 그대로 두고, 그 안의 의무를 **정본과 같은 구조**로만 꺼냈다.

## 구조 — 새 단위 종류를 만들지 않았다

| 층 | 무엇 | 이 폴더의 파일 |
|---|---|---|
| `unit` | **덩어리 원문 행 그대로**(정본 변경 없음) — 의무의 앵커 | (정본 `base_…\01_사실층\unit*.csv`) |
| `obl_master` 에 해당 | 덩어리 안 **1단 마디** 단위 의무 | `tech_obl_master.csv` (215행) |
| `obl_item` 에 해당 | 그 아래 **의무 술어가 있는 항목** = 체크 항목 | `tech_obl_item.csv` (1,281행) |

개정으로 항목 번호가 밀려도(4.1.2 → 4.1.3) **의무 앵커는 덩어리 조(unit)** 라 흔들리지 않는다.

## ★ 쓰기 전에 알아야 할 것

1. **전부 `review_status = pending` 이다.** 화면에 「검수 전」으로 보여야 하고, 「법적 확정」으로 표시하면 안 된다.
2. **제목 일부는 우리가 지었다.** 원문에 조문 제목이 없어 내용을 보고 만든 것이 전체 항목의 13.5%다(`제목 출처 = 생성`).
   의무 명칭도 「문서명 — 대표 항목 제목」으로 **우리가 조합한 이름**이다.
3. **문서 위험도 「상」 6문서(의무 53건)는 특히 조심.** 번호 체계가 7종까지 섞여 원문 계층을 확신할 수 없다.
   목록·근거: `master\(목록)덩어리조문_고시지침_반영보류_20260920.xlsx` · `40_지침_문서\분석_검토\(정리)덩어리조문_고시지침_특징과위험_20260920.html`
4. **용인시 해당은 규칙으로 붙인 후보다.** ① 문서가 용인시 보유·관리 시설을 다루거나 ② 본문 수범자가 관리주체·지자체장 계열이면 「Y(후보)」.
   실제 용인시 소관 여부는 FMS·원장DB로 확인해야 한다(메모리 `yongin-facility-subject-facts`).
5. **정본·그래프에 넣지 않는다.** 사용자 결정(09-20): 「원문(제목·편장절 구분)을 그대로 반영한 것이 아니므로, 완벽하게 검수하기 전에는 의무DB와 그래프DB에 반영하지 말자.」
   T-Box 「기술기준 항목」 신설 요청도 보류다(`contract\(요청)TBox_기술기준_항목단위_신설_20260920_v1.0.md` 맨 위 ⛔).
