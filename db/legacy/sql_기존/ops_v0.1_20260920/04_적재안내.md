# Supabase 적재 안내 — ops_v0.1 (용인시 데모 2차)

**SQL 실행은 사용자가 한다.** 아래 순서대로 하면 된다. 막히는 곳이 있으면 화면에 나온 문구를 그대로 알려 주면 고쳐서 다시 준다.

## 0. 준비 — 어느 프로젝트에 넣나

1차 데모가 들어 있는 Supabase 프로젝트를 그대로 써도 된다. **1차 표를 건드리지 않는다** — 새 스키마 `adoms2` 에만 만든다.
(Supabase 대시보드 → 해당 프로젝트 → 왼쪽 메뉴 **SQL Editor**)

## 1. 표 만들기 (SQL Editor)

`01_schema.sql` 전체를 복사해 붙여 넣고 **Run**.
→ `adoms2` 스키마에 표 13개가 생긴다. 다시 실행해도 안전하다(`if not exists`).

확인:
```sql
select table_name from information_schema.tables
where table_schema = 'adoms2' order by 1;
```
13줄이 나와야 한다 — action · asset · asset_target_map · compliance_task · duty_assignment · duty_class · evidence · form_template · inspection · notification · org_dept · staff (+ 이후 뷰).

## 2. 데이터 넣기 (Table Editor → Import data from CSV)

**`seed_utf8\` 폴더의 CSV 를 쓴다**(BOM 없는 사본 — 임포트가 첫 칸 이름을 잘못 읽지 않게 만들어 둔 것이다).
왼쪽 메뉴 **Table Editor** → 스키마를 `adoms2` 로 바꾸고 → 표를 고른 뒤 → 오른쪽 위 **Insert → Import data from CSV**.

**순서를 지킨다**(외래키 때문이다):

| # | 표 | 파일 | 행 | 크기 |
|---|---|---|---:|---:|
| 1 | `org_dept` | org_dept.csv | 15 | 0.6KB |
| 2 | `staff` | staff.csv | 28 | 2.5KB |
| 3 | `asset` | asset.csv | 1,026 | 192KB |
| 4 | `asset_target_map` | asset_target_map.csv | 2,134 | 113KB |
| 5 | `duty_class` | duty_class.csv | 2,876 | 2.8MB |
| 6 | `duty_assignment` | duty_assignment.csv | 4,652 | 637KB |
| 7 | `compliance_task` | compliance_task.csv | 2,717 | 199KB |
| 8 | `form_template` | form_template.csv | 131 | 19KB |

`evidence` · `inspection` · `action` · `notification` 은 **넣지 않는다**(화면에서 쌓인다).

★ 5번 `duty_class` 가 2.8MB 라 임포트가 느리거나 멈추면 알려 달라 — 500행씩 쪼갠 파일을 만들어 준다.

확인:
```sql
select 'duty_class' t, count(*) from adoms2.duty_class
union all select 'duty_assignment', count(*) from adoms2.duty_assignment
union all select 'compliance_task', count(*) from adoms2.compliance_task
union all select 'asset', count(*) from adoms2.asset
union all select 'form_template', count(*) from adoms2.form_template;
```
2,876 / 4,652 / 2,717 / 1,026 / 131 이 나와야 한다.

## 3. 뷰 만들기 (SQL Editor)

`02_views.sql` 전체를 붙여 넣고 **Run**. 뷰 6개가 생긴다.

확인 — 화면이 실제로 쓸 값이 나오는지 한 번에 본다:
```sql
select status, count(*) from adoms2.v_duty_todo group by 1 order by 2 desc;          -- 상태 5종
select dept_name, count(*) from adoms2.v_duty_todo group by 1 order by 2 desc limit 10;
select area, sum(total) from adoms2.v_kpi_summary group by 1;                         -- I·F·M
select count(*) from adoms2.v_asset_duty;                                             -- 자산 × 의무
```

## 4. 화면에서 읽을 수 있게 (권한)

데모는 읽기만 공개하고 쓰기는 막는다. **`anon`(publishable) 키만 화면에 쓴다 — `service_role` 키와 DB 비밀번호는 어디에도 붙여 넣지 않는다.**

```sql
-- 뷰만 읽기 허용
grant usage on schema adoms2 to anon, authenticated;
grant select on adoms2.v_duty_todo, adoms2.v_duty_detail, adoms2.v_asset_duty,
               adoms2.v_dept_progress, adoms2.v_law_tree, adoms2.v_kpi_summary
      to anon, authenticated;

-- 표는 직접 못 읽게 (화면은 뷰만 읽는다)
alter table adoms2.duty_class        enable row level security;
alter table adoms2.duty_assignment   enable row level security;
alter table adoms2.compliance_task   enable row level security;
alter table adoms2.asset             enable row level security;
alter table adoms2.asset_target_map  enable row level security;
alter table adoms2.org_dept          enable row level security;
alter table adoms2.staff             enable row level security;
alter table adoms2.form_template     enable row level security;
```
※ RLS 를 켜면 정책이 없는 한 anon 은 표를 못 읽는다(뷰는 위에서 허용했다). 쓰기(증빙 업로드·상태 변경)는 나중에 **공통 경로**(RPC 함수)로 연다 — 표에 직접 쓰지 않는다.

## 5. 끝났으면 알려 줄 것

3번의 확인 쿼리 결과 네 줄만 붙여 주면 된다. 그걸로 화면 설계에서 쓸 숫자를 맞춘다.
